# G-routine 설계 문서

- 작성일: 2026-10-05
- 상태: 검토 대기
- 한 줄 요약: 교사가 매일 해야 할 루틴을 바탕화면 우측 하단의 작은 위젯에 띄워 두고, 클릭으로 완료 처리하는 가벼운 Windows 데스크톱 앱

---

## 1. 목표와 범위

### 1.1 목표
1. 파스텔톤 · shadcn/ui 스타일의 깔끔하고 담백한 디자인
2. 가볍고 부담 없는 프로그램 (설치 파일 약 10MB 이하, 상주 메모리 최소화)
3. 출결 확인 · 수업 준비 · 누가기록 등 매일 할 일만 띄우고 클릭으로 완료
4. 나만의 루틴 추가 · 삭제
5. 날짜별 완료 내역 확인
6. 항상 맨 위에 표시 · 컴퓨터 켜면 자동 시작

### 1.2 사용 환경
- 교사 각자가 **개인 학교 PC(Windows 10/11)** 에 설치해 사용한다.
- 일부 학교 PC에는 재부팅 시 C드라이브를 초기화하는 **복원 프로그램**이 있다. 학교마다 다르므로 두 경우를 모두 지원한다.
- 관리자 권한 없이 설치 · 실행할 수 있어야 한다.

### 1.3 범위 밖 (이번에 하지 않음)
- **휴대폰 위젯 / 모바일 앱** — 보류. 추후 진행 시 저장소 계층을 클라우드 동기화로 교체하고 Android(Glance) 위젯을 붙인다. 이를 위해 반복 규칙 · 업무일 계산은 플랫폼 독립적인 Rust `core` 모듈에 둔다.
- 계정 · 로그인 · 서버 · 클라우드 동기화 — 데이터는 PC 로컬에만 저장한다.

## 2. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 앱 프레임워크 | **Tauri 2** | Windows 내장 WebView2 사용 → 설치 파일 약 5~10MB, 낮은 메모리. Electron(80~150MB) 대비 "가벼움" 목표 충족 |
| 화면 | React + TypeScript + Vite | shadcn/ui 사용을 위해 |
| 스타일 | Tailwind CSS + **shadcn/ui** | 요구 디자인. 컴포넌트 소스를 프로젝트에 복사하므로 파스텔 테마로 자유롭게 수정 가능 |
| 백엔드 로직 | Rust | 반복 규칙 · 업무일 계산 · DB 접근의 단일 진실 공급원 |
| 저장소 | **SQLite** (`rusqlite`, bundled) | 갑작스러운 전원 차단에도 트랜잭션 보장. 파일 1개라 백업이 쉬움 |
| Tauri 플러그인 | autostart, single-instance, opener, dialog, (2단계) global-shortcut, notification, (3단계) updater | 공식 플러그인으로 OS 기능 처리 |

개발 환경: Node 24, Rust 1.96 확인됨.

## 3. 기능 명세

### 3.1 1단계 — MVP

| # | 기능 | 상세 |
|---|---|---|
| F1 | 오늘의 루틴 목록 | 위젯 창에 오늘 업무일의 미완료 항목을 표시. 체크 시 페이드아웃되며 목록에서 사라짐 |
| F2 | 되돌리기 | 체크 직후 3초간 "○○ 완료 · 되돌리기" 토스트 |
| F3 | 완료 항목 보기 | 하단 "완료 n개 보기"를 펼쳐 오늘 완료한 항목 확인 · 체크 해제 |
| F4 | 진행률 | 상단 `완료 / 전체` 숫자 + 파스텔 진행 바. 전부 완료 시 "모두 완료 ✓" 및 민트색 바 |
| F5 | 루틴 추가 · 삭제 · 순서 변경 | 관리 창 "루틴 관리" 탭. 이름, 반복 규칙, 바로가기 지정. 드래그로 순서 변경 |
| F6 | 반복 규칙 | `매일` / `요일 지정`(월~금 중 복수 선택) / `오늘만`(일회성) |
| F7 | 오늘 할 일 빠른 추가 | 위젯 하단 입력란에 입력 후 Enter → `오늘만` 루틴으로 생성 |
| F8 | 하루 시작 시각 | 업무일 경계 시각 설정 (기본 오전 4:00) |
| F9 | 주말 숨김 | 토 · 일에는 목록 대신 "좋은 주말 보내세요" 표시 (설정에서 끌 수 있음) |
| F10 | 날짜별 완료 기록 | 관리 창 "완료 기록" 탭. 월 달력에 달성률을 라벤더 농도로 표시. 날짜 클릭 시 완료 항목(시각 포함)과 **미완료 항목** 표시 |
| F11 | 항상 맨 위에 표시 | 설정 토글 + 위젯 헤더 핀 아이콘 + 트레이 메뉴 |
| F12 | 컴퓨터 켜면 자동 시작 | 설정 토글 + 트레이 메뉴 (`tauri-plugin-autostart`, HKCU Run) |
| F13 | 트레이 아이콘 | 위젯을 숨겨도 트레이에 상주. 클릭 시 위젯 표시. 메뉴: 위젯 보이기, 관리 창, 맨 위 고정, 자동 시작, 종료 |
| F14 | 위치 기억 | 기본 위치는 주 모니터 작업 영역의 우측 하단(여백 12px). 드래그 시 위치 저장. 저장 위치가 현재 모니터 범위를 벗어나면 기본 위치로 복귀 |
| F15 | 저장 폴더 선택 | 첫 실행 시 저장 위치 선택. D드라이브가 있으면 `D:\G-routine` 기본 제안 및 "복원 프로그램이 있는 PC는 D드라이브 권장" 안내 |
| F16 | 기본 루틴 템플릿 | 첫 실행 시 `담임` / `교과전담` / `비어있음` 중 선택 |
| F17 | 백업 / 불러오기 | 전체 데이터를 `.json` 파일로 내보내기 · 가져오기 (가져오기 시 현재 데이터를 덮어쓰기 전 확인) |
| F18 | **바로가기 연결** | 루틴에 웹 주소(https) 또는 프로그램/파일 경로 연결. 위젯에서 ↗ 아이콘 클릭 시 열기. 열기와 완료 체크는 별개 |

#### 기본 템플릿 내용
- **담임**: 출결 확인(매일, NEIS 링크) · 수업 준비(매일) · 누가기록 작성(매일) · 공문 확인(매일) · 알림장/학급 공지(매일) · 주간학습안내 배부(금)
- **교과전담**: 수업 준비(매일) · 공문 확인(매일) · 수업 기록/진도 체크(매일) · 수행평가 기록(매일)
- 모든 항목은 첫 실행 후 자유롭게 수정 · 삭제 가능.

### 3.2 2단계 — 편의 기능
- 시간대 그룹(조회 전 / 수업 중 / 방과 후)
- 마감 시각 알림 (`due_time`까지 미완료 시 Windows 알림 1회)
- 미니 모드 (알약 형태 `✓ 3/7`, 마우스 올리면 펼침)
- 방학 모드(기간 지정 일시정지) · 대한민국 공휴일 자동 숨김
- 전역 단축키 `Ctrl+Alt+G` (보이기/숨기기)
- 투명도 · 글자 크기 조절
- 연속 달성 기록 표시
- 완료 기록 CSV 내보내기

### 3.3 3단계 — 배포
- 사용자 단위 설치 파일(NSIS, `currentUser`, 관리자 권한 불필요) + **포터블 exe**
- 자동 업데이트 (GitHub Releases + `tauri-plugin-updater`)
- 설치 안내 페이지 (복원 프로그램 PC 설치 순서 포함)

## 4. 화면 구성

### 4.1 위젯 창 (`widget`)
- 크기 약 280 × 가변 높이(최대 420px, 넘으면 목록 내부 스크롤). 프레임 없음(decorations: false), 둥근 모서리, 작업표시줄에 표시 안 함(skipTaskbar).
- 구성(위→아래): 헤더(날짜 · 핀 · ⚙ 관리 창 · – 숨기기) → 진행률 → 오늘 목록 → 되돌리기 토스트 → "완료 n개 보기" → 빠른 추가 입력란.
- 헤더 영역은 드래그로 창 이동(`data-tauri-drag-region`).

### 4.2 관리 창 (`manager`)
- 일반 창(약 720 × 520). 위젯의 ⚙ 또는 트레이 메뉴로 열고, 닫으면 WebView를 해제해 메모리 반환.
- 탭: **루틴 관리** / **완료 기록** / **설정**.
- 설정 항목: 항상 맨 위, 자동 시작, 주말 숨김, 하루 시작 시각, 테마색(라벤더 · 민트 · 피치 · 스카이 · 레몬), 데이터 저장 위치(변경), 백업 내보내기 · 불러오기.

### 4.3 디자인 토큰
- 기본 테마: 라벤더 (`#EEEDFE` / `#CECBF6` / `#AFA9EC` / `#7F77DD` / `#534AB7`)
- 칩 색 의미: 라벤더 = 매일, 민트 = 요일 지정, 피치 = 오늘만, 레몬 = 마감 시각
- 배경 흰색, 0.5~1px 연한 테두리, 그림자 최소화, 모서리 8~12px. 폰트: Pretendard(번들) → 시스템 폰트 대체.
- 라이트 모드 우선. 다크 모드는 2단계 이후 검토.

## 5. 데이터 모델

### 5.1 테이블

```sql
CREATE TABLE routines (
  id           INTEGER PRIMARY KEY,
  title        TEXT    NOT NULL,
  repeat_type  TEXT    NOT NULL CHECK (repeat_type IN ('daily','weekdays','once')),
  weekdays     INTEGER NOT NULL DEFAULT 0,  -- 비트: 월=1 화=2 수=4 목=8 금=16 토=32 일=64
  once_date    TEXT,                        -- 'YYYY-MM-DD', repeat_type='once'일 때만
  due_time     TEXT,                        -- 'HH:MM'. MVP: 입력 + 레몬 칩 표시만, 알림은 2단계
  link         TEXT,                        -- https URL 또는 로컬 경로
  sort_order   INTEGER NOT NULL,
  created_at   TEXT    NOT NULL,
  archived_at  TEXT                         -- 삭제 시각 (soft delete)
);

-- 업무일별 "해야 할 일" 스냅샷 + 완료 여부
CREATE TABLE day_items (
  id             INTEGER PRIMARY KEY,
  day            TEXT    NOT NULL,          -- 업무일 'YYYY-MM-DD'
  routine_id     INTEGER NOT NULL REFERENCES routines(id),
  title_snapshot TEXT    NOT NULL,
  sort_order     INTEGER NOT NULL,
  completed_at   TEXT,                      -- NULL = 미완료
  UNIQUE (day, routine_id)
);

CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

-- PRAGMA user_version 으로 스키마 버전 관리
```

### 5.2 핵심 규칙

| 규칙 | 정의 |
|---|---|
| **업무일** | `business_day(now) = date(now − day_start_hour)`. 기본 4시 → 10/6 01:30은 업무일 10/5 |
| **해당 여부** | `daily`: 항상 · `weekdays`: 업무일의 요일 비트가 켜져 있음 · `once`: `once_date == 업무일` · 공통: `archived_at`이 NULL |
| **주말 숨김** | `hide_weekends`가 켜져 있고 업무일이 토·일이면 그날 스냅샷을 만들지 않음 (`daily` 포함) |
| **스냅샷 생성** | 앱이 어떤 업무일을 처음 다룰 때, 해당 루틴을 `day_items`에 삽입 (`INSERT OR IGNORE`) |
| **오늘 스냅샷 동기화** | 루틴을 추가 · 수정 · 삭제하면 **오늘 업무일만** 다시 맞춤: 새로 해당되는 루틴 추가, 더 이상 해당하지 않는 **미완료** 항목 제거, 완료 항목은 유지. 과거 업무일은 절대 수정하지 않음 |
| **완료 / 해제** | `completed_at`을 현재 시각으로 채우거나 NULL로 되돌림 |
| **"오늘만" 미완료** | 업무일이 지나면 목록에서 사라지고 그날 `day_items`에 `completed_at = NULL`로 남아 기록 화면에서 "미완료"로 표시. 이월하지 않음 |
| **지난 "오늘만" 루틴** | `once_date`가 오늘 업무일보다 이전인 루틴은 루틴 관리 탭에 표시하지 않음 (기록은 `day_items`에 남음) |
| **이름 변경** | 오늘의 미완료 `title_snapshot`만 갱신. 과거 기록은 당시 이름 유지 |
| **기록 없는 날** | 앱이 실행되지 않은 날은 `day_items`가 없음 → 달력에서 "기록 없음"(빈칸)으로 표시, 0%와 구분 |
| **달성률** | `완료 수 / 해당 날짜 day_items 수`. 4단계 농도: 0%, 1~49%, 50~99%, 100% |
| **날짜 넘김 감지** | 1분 주기 타이머 + 절전 복귀/창 포커스 시 업무일 재계산. 바뀌면 스냅샷 생성 후 `data-changed` 이벤트 |

### 5.3 저장 위치 해석 (복원 프로그램 대비)
1. 실행 파일 옆에 `data/` 폴더가 있으면 그것을 사용 (포터블 모드)
2. 앱 설정 파일(`%AppData%\G-routine\location.json`)에 기록된 경로
3. 없으면 자동 탐색: `D:\G-routine\data` → 다른 고정 드라이브의 `\G-routine\data` 순서로 `g-routine.db` 검색 → 발견 시 재연결하고 2번에 다시 기록
4. 그래도 없으면 첫 실행 화면(저장 폴더 선택 + 템플릿 선택)

## 6. 아키텍처

```text
src/                       React (화면 전용, 로직 없음)
  windows/widget/          위젯 창
  windows/manager/         관리 창 (routines / history / settings 탭)
  components/ui/           shadcn/ui 컴포넌트 (파스텔 테마 적용)
  lib/api.ts               invoke() 래퍼 + 타입
src-tauri/src/
  core/                    업무일 · 반복 규칙 · 스냅샷 동기화 (순수 함수, DB 비의존)
  db/                      SQLite 연결, 마이그레이션, 쿼리
  storage/                 저장 위치 해석, 자동 백업, JSON 내보내기/가져오기
  commands.rs              Tauri 명령 (아래 표)
  shell/                   창 위치 계산(작업 영역 기준), 트레이, 맨 위 고정
  lib.rs                   플러그인 등록, 앱 시작
```

### 6.1 명령 (화면 → Rust)

| 명령 | 설명 |
|---|---|
| `get_today()` | 오늘 업무일, 미완료 · 완료 목록, 진행률 |
| `set_done(item_id, done)` | 완료 / 해제 |
| `quick_add(title)` | `오늘만` 루틴 생성 + 오늘 스냅샷 추가 |
| `list_routines()` / `create_routine()` / `update_routine()` / `archive_routine()` / `reorder_routines()` | 루틴 관리 |
| `history_month(year, month)` | 날짜별 달성률 |
| `history_day(day)` | 그날 항목 목록 (완료 시각 · 미완료 포함) |
| `get_settings()` / `set_setting(key, value)` | 설정 (맨 위 고정 · 자동 시작은 즉시 OS에 반영) |
| `open_link(routine_id)` | 등록된 링크 열기 (ID로만 호출 → 임의 경로 실행 방지) |
| `export_backup(path)` / `import_backup(path)` | 백업 |
| `choose_data_dir(path)` | 저장 위치 변경 (기존 DB 이동 또는 연결) |

데이터를 바꾸는 명령은 끝에 `data-changed` 이벤트를 모든 창에 보내 위젯과 관리 창을 동시에 갱신한다.

## 7. 오류 처리

| 상황 | 대응 |
|---|---|
| 저장 폴더 없음 (드라이브 분리 등) | "저장 폴더를 찾을 수 없어요" 화면: 다시 찾기 / 다른 폴더 선택 / 새로 시작 |
| DB 손상 | 업무일 첫 실행 시 `data/backups/g-routine-YYYY-MM-DD.db` 자동 백업(최근 7개 유지). 열기 실패 시 최근 백업 복구 제안 |
| 쓰기 실패 | 화면 상태를 원래대로 되돌리고 "저장하지 못했어요. 다시 시도" 토스트 |
| 중복 실행 | single-instance: 기존 위젯을 표시하고 포커스 |
| 링크 열기 실패 | "링크를 열 수 없어요. 주소를 확인하세요" 토스트 |
| 위치가 화면 밖 (모니터 변경) | 기본 위치(우측 하단)로 복귀 |
| 백업 파일 형식 오류 | 가져오기 전 검증, 현재 데이터 변경 없이 오류 안내 |

## 8. 테스트

- **Rust 단위 테스트 (`cargo test`)** — `core`: 업무일 경계(03:59/04:00, 자정), 요일 비트, `once` 해당 여부, 주말 숨김, 오늘 스냅샷 동기화(완료 항목 보존, 과거 불변), 이름 변경 시 스냅샷 처리. `db`: 마이그레이션, UNIQUE 중복 방지. `storage`: 저장 위치 해석 순서, 백업 순환(7개).
- **화면 테스트 (Vitest + Testing Library)** — 체크 → 사라짐 → 되돌리기, 진행률 계산 표시, 빠른 추가.
- **수동 점검표** — 화면 배율 100/125/150%, 듀얼 모니터, 자동 시작 후 재부팅, 절전 복귀 시 날짜 넘김, 복원 프로그램 시나리오(AppData 삭제 후 D드라이브 자동 재연결), 설치 파일 크기 · 유휴 메모리 측정.

## 9. 성공 기준
- 설치 파일 15MB 이하, 위젯만 떠 있을 때 메모리 약 80MB 이하
- 체크 클릭부터 화면 반영까지 100ms 이내
- 복원 프로그램 환경에서 재부팅 후에도 루틴 · 기록 유지 (D드라이브 저장 시)
- 위 단위 테스트 전부 통과
